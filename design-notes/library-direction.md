# component and motion expansion

## scope

keep the approved Siftion UI font binaries, four-color active palette, oversized wordmark, and editorial page structure. replace the generic actions in section 03 with a reusable, distinct control family. expand components and motion into practical patterns. rewrite all public copy, including messages generated by JavaScript.

## references inspected

- https://tympanus.net/codrops/2020/08/05/magnetic-buttons/
  - observed in the article: bounded pointer-following buttons, fill/border animations, and layered movement.
  - transferable: give the arrow, label, and surface distinct but coordinated responses; keep the hit area stable.
  - do not copy: a permanent animation loop, mouse-only operability, dependencies installed from a registry without review, or every demonstrated effect at once.
- https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
  - modal content contains focus; the background is inert; closing restores the user's place.
- https://www.w3.org/WAI/ARIA/apg/patterns/switch/
  - stable label with on/off state. changing state must not change the control's accessible name.
- https://www.w3.org/WAI/ARIA/apg/patterns/accordion/
  - expandable headings need truthful expanded state and a relationship to the controlled panel, or an appropriate native disclosure.

these references inform original static HTML/CSS/JS implementations. no external component package is required.

## interaction contract

- button hover and focus: the same readable affordance, with stable layout and hit area.
- press: immediate tactile feedback; no motion that moves the target away from a click.
- pending action: explicit busy state and duplicate-activation prevention. demo timing is identified as a demonstration, not an external request.
- confirmation: visible text or icon with an accessible announcement; offer reset or undo where the underlying action is reversible.
- modal/disclosure/selection: state reflected in native properties or ARIA, operated by keyboard as well as pointer.
- motion recipes: explicit trigger, property, duration, easing, interruption behavior and reduced-motion equivalent. replay must restart predictably instead of accumulating timers.
- reusable snippets: real classes and behavior hooks, with required assets identified. no decorative snippet claiming to implement functionality it omits.
